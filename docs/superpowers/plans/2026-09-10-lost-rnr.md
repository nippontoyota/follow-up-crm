# LOST RNR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Call Executives close a lead as `LOST RNR` after three prior follow-ups, while keeping every role and report consistent.

**Architecture:** Add one canonical closing outcome to the existing outcome map and loss sets. The frontend exposes it only for the next attempt after F3 and only under `Not Connected`; the server independently enforces the same rule. Existing stage-based closed-lead metrics continue to work, while outcome-based lost reports, AI analysis, and exports explicitly include `LOST RNR`.

**Tech Stack:** Express, PostgreSQL, vanilla JavaScript, existing Node smoke/static checks, GitHub-to-Render deployment.

## Global Constraints

- No schema change is required.
- Do not alter existing leads or follow-ups.
- Do not add extra requests or polling.
- Only Call Executives and Admin may submit `LOST RNR`; managers remain read-only for follow-ups.
- `LOST RNR` is valid only when the lead already has at least three follow-ups and the submitted call status is `Not Connected`.
- Closing `LOST RNR` must set the lead to `Lost Lead`, `closed`, and no next follow-up date.
- Reports must keep `LOST RNR` separate from customer-declared loss reasons.
